# 线路服务增强开发计划

> 背景：当前内置 4 条线路来自 [Alvin9999/PAC](https://gitlab.com/Alvin9999/PAC)，节点池质量已严重下降（3/4 节点已死：fan2.856098.xyz、hy2.561891.xyz、83.243.86.109），用户失去可用节点。本计划为「线路服务」栏目增加 4 项能力，分 4 批交付，每批单独发版。

---

## 总体设计

### 目标能力

| 编号 | 能力 | 价值 | 优先级 |
|------|------|------|--------|
| A | **自定义订阅**（Clash YAML） | 让用户接入自己的机场，彻底摆脱内置节点失效问题 | P0 |
| B | **IP 区域/国家筛选** | 只保留用户需要的国家节点，提升选择效率 | P1 |
| C | **节点健康度统计** | 自动识别"哪条线最近好使"，避免每次手动 4 选 1 | P2 |
| D | **多上游支持** | 主仓库失效时自动切备选，降低单点故障 | P3 |

### 关键技术选型

| 维度 | 决策 | 理由 |
|------|------|------|
| 订阅格式 | **仅 Clash YAML** | 90%+ 机场支持，解析简单 |
| IP 地理 | **本地 GeoIP mmdb** | 复用软件已有的 `Country.mmdb`，离线可用 |
| 持久化 | **本地 JSON** | `dev/app/user_data/subscriptions.json`、`health.json` |
| 发布节奏 | **每 Batch 独立发版** | 边用边反馈，定位问题快 |

### 数据流改造

```
当前：
  内置 4 条 URL → download_all_configs() → save_config() → 测速

改造后：
  内置 4 条 URL  ┐
  用户自定义订阅 ┴─→ download_all_configs() 合并 → 测速 → 健康度记录
                                          ↑
                                    [B 阶段] 国家筛选
                                    [C 阶段] 健康度排序
                                    [D 阶段] 主备自动切换
```

## Batch 1：自定义订阅（Clash YAML）

### 目标
让用户能添加自己的机场订阅，软件解析后并入检测线路列表。

### UI 改动（线路服务栏目顶部）
- 新增「📋 订阅管理」按钮 → 弹出子页面
- 子页面内容：
  - 顶部：URL 输入框 + 「添加订阅」按钮 + 备注名输入
  - 列表区：每行 = [启用☑] [备注名] [URL] [节点数N] [延迟?] [删除🗑]
  - 底部：「立即刷新全部订阅」按钮

### 文件改动
- `dev/app/main.py`:
  - 新增 `Subscription` 数据类（url, name, enabled, last_update, node_count, last_latency）
  - 新增 `SubscriptionManager` 类（load/save/add/remove/toggle，存 `dev/app/user_data/subscriptions.json`）
  - 新增 `parse_clash_yaml(text) -> dict` 解析函数（提取 proxies 段、proxy-groups 段、rules 段）
  - 新增 `download_subscription(sub) -> (name, data)` 下载+解析一条订阅
  - **修改** `download_all_configs()` 合并内置 + 自定义订阅
  - 新增 `open_subscription_dialog()` UI 函数
  - 在线路服务栏目加「📋 订阅管理」按钮入口

### 验收标准
- [ ] 用户能粘贴订阅 URL 并添加
- [ ] 软件正确解析 Clash YAML（含 proxies/proxy-groups/rules）
- [ ] 检测线路时把自定义订阅一并测速
- [ ] 关闭软件后订阅列表不丢失
- [ ] 能启用/禁用/删除单条订阅
- [ ] 下载失败的订阅给出明确错误提示（不阻塞其他订阅）

### 风险点
- 订阅格式不完全标准（部分机场有自定义字段）→ 用宽松解析，只取必要字段
- 订阅 URL 可能有 base64 编码 → 加 `try base64` fallback
- 订阅节点过多导致启动慢 → 加节点数上限（默认 200）

### 发版
- 版本号：`v2026.06.18.1300` 之后
- 文件：自定义订阅版

## Batch 2：IP 区域/国家筛选

### 目标
解析每个节点 server IP 对应的国家，让用户能"只保留美国/日本节点"。

### UI 改动
- 线路服务栏目顶部新增「🌍 国家筛选」按钮 → 弹国家多选
- 订阅管理列表里每行新增「🌍 12 节点 (🇺🇸8 🇯🇵4)」国家分布
- 检测线路结果表格新增「国家」列

### 文件改动
- `dev/app/main.py`:
  - 新增 `ensure_geoip_db()` 启动时检查 `Country.mmdb` 是否存在，不存在则自动下载
  - 新增 `lookup_country(ip) -> str` 用 maxminddb 查国家码
  - 新增 `resolve_node_country(server) -> str` 节点 server 可能是域名，先 DNS 再查
  - 新增 `get_node_countries(config) -> Dict[proxy_name, country_code]`
  - **修改** `save_config()` 在保存前根据用户的国家白名单筛选（删除不在白名单的 proxy 及其引用）
  - **修改** 代理设置 → 节点选择页：每行新增国家标记
  - 新增 `CountryFilter` UI 组件（多选下拉框）
  - 持久化：`dev/app/user_data/settings.json` 加 `country_whitelist: []`

### 验收标准
- [ ] 节点列表能看到每个节点的国家（🇺🇸/🇯🇵 等 emoji）
- [ ] 用户能多选国家（如：🇺🇸 + 🇯🇵）
- [ ] 切线后只剩选中国家的节点
- [ ] 不在白名单的节点在代理设置页面标灰
- [ ] mihomo 启动时不会因为"proxy-groups 引用被删的 proxy"报错

### 关键技术细节
- **mmdb 来源**：从 [maxmind.com](https://www.maxmind.com/en/geolite2/signup) 下载 GeoLite2-Country（免费），或用现成 CDN
- **DNS 解析**：用 `socket.gethostbyname()`，解析失败标 ❓
- **proxy-groups 引用清理**：mihomo 不允许 group 引用不存在的 proxy，删除 proxy 时要扫描所有 group 的 `proxies: []` 和 `use: []`
- **性能**：100 节点的 DNS + GeoIP 查询 < 2s

### 风险点
- mmdb 文件 ~60MB，启动慢 → 启动时异步加载
- 部分机场的节点 server 是 CDN 域名（如 `cdn.example.com`）→ 标 ❓ 让用户手动选
- 国内节点不需要代理 → 规则 `GEOIP,CN,DIRECT` 已处理，不需要在节点层过滤

### 发版
- 版本号：`v2026.06.19.xxxx`
- 文件：IP 区域筛选版

## Batch 3：节点健康度统计

### 目标
自动记录每条线路的检测结果，UI 显示历史成功率，自动按健康度排序。

### UI 改动
- 检测线路结果表格新增「7 天成功率」列（百分比+小条形图）
- 表格按健康度默认排序（好的在上面）
- 新增「📊 健康度详情」按钮 → 弹 30 天历史折线图

### 文件改动
- `dev/app/main.py`:
  - 新增 `HealthRecord` 数据类（line_name, timestamp, success, avg_latency, best_latency）
  - 新增 `HealthDB` 类（append/get_7d_success_rate/get_30d_history，存 `dev/app/user_data/health.json`，自动 trim 30 天前数据）
  - **修改** `_do_test_lines` 每条线测完后调 `health_db.append(...)`
  - **修改** `_do_auto_select` 健康度优先于速度
  - 新增 `format_health_bar(rate)` 渲染条形图（▁▂▃▄▅▆▇█ 8 档）
  - 排序：健康度 desc → 延迟 asc

### 数据格式
```json
{
  "线路1": [
    {"ts": "2026-06-18T12:00:00", "success": true, "avg": 0.42, "best": 0.38},
    {"ts": "2026-06-18T13:00:00", "success": false, "avg": -1, "best": -1}
  ]
}
```

### 验收标准
- [ ] 每次检测完自动记录到 health.json
- [ ] UI 显示每条线的 7 天成功率（百分比）
- [ ] 表格默认按健康度排序
- [ ] health.json 自动清理 30 天前数据
- [ ] 软件升级/重装数据不丢失

### 风险点
- JSON 文件过大 → 30 天 cap 4 条线 × 24h × 12 次/h = 11520 条 ≈ 2MB，可接受
- 频繁写文件 → 批量写（每 5 分钟 flush 一次）

### 发版
- 版本号：`v2026.06.20.xxxx`
- 文件：健康度统计版

## Batch 4：多上游支持

### 目标
主仓库失效时自动切到备选仓库下载线路配置。

### 调研候选（待确认）

| 当前 | `https://www.gitlabip.xyz/Alvin9999/PAC/.../quick/{1-4}/config.yaml` | ⚠️ 节点已死 | 主仓库 |
| 备选 1 | 待调研 | - | - |
| 备选 2 | 待调研 | - | - |

> **本 Batch 需要先做 1-2 天的调研**，确认至少 2 个可用备选仓库再写代码。

### 文件改动
- `dev/app/main.py`:
  - 新增 `BACKUP_CONFIG_URLS` 列表
  - **修改** `download_config` 接受多组 (primary, fallback) URL 列表
  - **修改** `download_all_configs` 主组全失败时降级到备选组
  - 新增 UI 标识当前数据来源（如「线路1 (主仓库)」vs 「线路1 (备选仓库)」）

### 验收标准
- [ ] 主仓库失效时备选仍能下载
- [ ] UI 明确标识当前数据来源
- [ ] 主备切换不丢已下载的有效配置

### 风险点
- 备选仓库节点质量更差 → 在 Batch 3 健康度统计加持下会自动识别
- 备选仓库可能没有 4 条线 → 支持 N 条任意

### 发版
- 版本号：`v2026.06.21.xxxx`（视调研结果定）
- 文件：多上游版
